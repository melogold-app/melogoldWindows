# Диагностика: «Сохранить журнал…» — журнал одним файлом

Статус: сделано — `Melogold.Core`: `LogReport` (шапка, разделы, имя файла; имена файлов журнала — отсюда же, их берёт
`Log`), `Melogold.App`: `Log.Report`, кнопка «Сохранить журнал…» в «Диагностике» (`SettingsPage.OnSaveLog`); тесты
`LogReportTests` на Linux проверены через .NET 10 SDK; приложение (WinUI) на Linux не собирается — его проверит CI на
Windows после push

Максим (31.10.2026): «сделай во всех клиентах, чтобы логи уходили файлом».

## Что не так

Журнал пишется тремя файлами в `%LOCALAPPDATA%\Melogold\logs` (`Services/Log.cs`): `current.log` этого запуска (до 2 МБ),
`previous.log` прошлого и `last-crash.txt` последнего падения. В настройках была только «Открыть папку»: чтобы прислать
журнал, человеку надо найти и приложить три файла.

## Как должно быть

- «Настройки › О приложении › Диагностика»: рядом с «Открыть папку» — «Сохранить журнал…» / "Save log…".
- Нажатие — системный диалог сохранения (по умолчанию «Документы»), имя `melogold-log-ГГГГММДД-ЧЧММ.txt`, тип
  «Текстовый файл». Сохранилось — «Журнал сохранён», нет — «Не удалось сохранить журнал» (и строка в журнал).
- Файл — один текст в UTF-8. Шапка:
  ```
  Melogold 0.1.20
  Время: 2026-10-31 03:07:45 +03:00
  Windows: 11 24H2, сборка 26100.4652
  Архитектура: x64
  ```
  Время — в формате строк журнала, с поясом. Windows 11 или 10 — по сборке (как в списке устройств аккаунта), выпуск и
  номер обновления — из реестра (`DisplayVersion`, `UBR`); не прочитались — только сборка. Если система другой
  архитектуры, чем сборка приложения (x64 на Windows для ARM), — она тоже: «x64, Windows arm64».
- Дальше разделы, как у Android (`LogFiles.export`): `===== Падение (last-crash.txt) =====`, `===== Прошлый запуск
  (previous.log) =====`, `===== Этот запуск (current.log) =====` — каждый с текстом файла. Файла нет — нет и раздела.
- Файлы журнала открыты на запись — читаются с `FileShare.ReadWrite` и `Delete`: перенос `current.log` в `previous.log`
  на 2 МБ во время чтения не должен сломать журнал до конца запуска.
- Ничего, кроме того, что уже в журнале: пароли и токены туда не пишутся.

Если этот запуск перерос 2 МБ, `Log` переносит его начало в `previous.log` (поверх прошлого запуска) — тогда «Прошлый
запуск» на деле начало этого. Так журнал вёл себя и раньше, здесь не менялось.

## Проверка

- `LogReportTests`: шапка целиком; имя файла; три раздела по порядку после шапки; нет `last-crash.txt` — нет «Падения»;
  нет папки — одна шапка; `current.log`, открытый на запись, как его держит `Log`, читается (на Windows — проверка
  `FileShare`, на Linux .NET общий доступ не ограничивает).
- Вживую на Windows: «Сохранить журнал…» → файл в «Документах», в нём шапка с версией и сборкой Windows и разделы.
