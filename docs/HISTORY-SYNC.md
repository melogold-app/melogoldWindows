# История прослушиваний через сервер: задание для Windows-клиента

Дополнение к `docs/PROMPT.md`. Работай по нему параллельно с сессией на Mac: она делает то же в Android. Сервер уже умеет всё нужное — это поток `history` в `POST /sync`. Контракт не меняй. Если чего-то не хватает, скажи пользователю.

## 1. Что нужно пользователю

- История общая: трек, прослушанный на любом устройстве, появляется в Истории на всех.
- В Истории можно смотреть по устройствам: «Все устройства» (по умолчанию), «Это устройство» и каждое другое устройство аккаунта по имени.
- «Убрать из истории» и «Очистить историю» действуют на всех устройствах.

## 2. Контракт сервера (melogoldServer `docs/API.md` §4.8, DESIGN §3.6–§3.7)

**Поток и курсор:**
- `POST /sync` с `streams: ["library", "history"]` (или без `streams` — тогда оба). Курсор общий, но позиция у каждого потока своя.
- Если клиент раньше синхронизировал только `library`, позиция истории в его курсоре — 0. Первый запрос с `history` отдаёт всю историю, страницами, пока `hasMore`.

**Ops истории:**

| kind | Поля | Когда |
|---|---|---|
| `play.add` | `opId` = eventId (UUID события), `at` = `playedAt`, `videoId`, `playedAt`, `playTimeMs` (1..86 400 000), `history: true`, `playtime: true`, `tracks` (метаданные трека) | каждое прослушивание |
| `history.forget` | `videoId`, `eventsBefore` = сейчас, `resetTotal: false` | «Убрать из истории» |
| `history.clear` | `eventsBefore` = сейчас | «Очистить историю» |
| `play.baseline` | `mode: "atLeast"`, `entries` (до 500 `{videoId, totalMs}`) | один раз, если есть накопленное время прослушивания до синка (импорт) |

- `play.add` идемпотентен по `opId`. Повтор даёт `applied, replayed: true`.
- `deferred op_rate_limited` (больше 2000 `play.add` в час) — отложить до `retryAfterSeconds`.
- Лимиты в `/server/info` → `limits.history`:
  - `retentionDays` 400 — сервер хранит события 400 дней;
  - `maxEvents` 50 000;
  - `mergeUploadMax` 20 000 — столько последних событий отправить при первом синке, не больше.

**Строки ответа:**
- `plays[]` — `{eventId, videoId, playedAt, playTimeMs, deviceId}`. Событие любого устройства; `deviceId` — кто слушал.
- `playStats[]` — `{videoId, totalPlayTimeMs, lastPlayedAt}`, общее время трека по всем устройствам.
- `playForgets[]` — `{videoId | "*", eventsBefore, totalBefore}`: события трека (или все при `"*"`) с `playedAt ≤ eventsBefore` удалены.
- Метаданные треков из `plays` приходят в `tracks[]` того же ответа.

**Имена устройств** — `GET /auth/me/devices`, `id` → `name`. У текущего устройства `isCurrent: true`.

## 3. Что сделать в клиенте

Так же сделает и Android, чтобы клиенты вели себя одинаково.

1. **Событие прослушивания.** Когда трек закончился или сменился и реально проиграно не меньше 5 с (как на Android), записать событие:
   - `eventId` — новый UUID;
   - `videoId`;
   - `playedAt` — момент конца прослушивания;
   - `playTimeMs` — сколько реально играло;
   - `deviceId` — пусто (значит «это устройство»);
   - `sent: false`.

   Общее время трека локально тоже растёт. История пишется и без аккаунта.
2. **Отправка** — внутри общего цикла синка:
   - неотправленные события уходят `play.add`, по 500 op за запрос, с `tracks`;
   - `applied` (в том числе `replayed`) и `superseded` → `sent = true`;
   - `deferred` → оставить, повторить после `retryAfterSeconds`; `rejected` → `sent = true`, чтобы не слать вечно;
   - при первом синке с аккаунтом — не больше `mergeUploadMax` самых свежих событий, а накопленное время треков — одним `play.baseline atLeast`.
3. **Загрузка:**
   - `plays` → вставить событие, если такого `eventId` ещё нет, с его `deviceId` и `sent = true`. Своё событие, вернувшееся с сервера, не задваивается;
   - `playStats` → общее время трека = значение сервера (оно уже включает все устройства);
   - `playForgets` → удалить локальные события трека (или все) с `playedAt ≤ eventsBefore`.
4. **«Убрать из истории» и «Очистить историю»:**
   - удалить локально и отправить `history.forget` или `history.clear`;
   - подтверждение и «Отменить» — как у других разрушающих действий;
   - подпись должна говорить, что действие — для всех устройств.
5. **Фильтр по устройствам в Истории:**
   - в шапке страницы — выбор «Все устройства · Это устройство · <имя устройства>…», стандартный контрол Fluent (`ComboBox` или `DropDownButton` с меню);
   - виден, только когда есть аккаунт и события с других устройств;
   - «Это устройство» — события без `deviceId` и с `deviceId` текущего устройства;
   - устройство, которого уже нет в списке, называется «Другое устройство»;
   - «Недавние» — события выбранного устройства по времени;
   - «Чаще всего» за период — сумма `playTimeMs` событий выбранного устройства за период; «Всё время» для «Все устройства» — общее время трека (`playStats`).
6. **Смена аккаунта или сервера** — как у библиотеки: курсор с нуля, все свои события снова `sent: false` (их примет новый аккаунт), чужие события прошлого аккаунта удалить.

## 4. Проверка

- **Юнит-тесты:** разбор строк ответа, идемпотентность по `eventId`, забывание по `playForgets`, фильтр по устройствам.
- **Сквозная проверка на живом сервере:**
  - трек, прослушанный на Android, через секунды виден в Истории Windows с именем устройства Android, и наоборот;
  - «Убрать из истории» на одном устройстве убирает трек на другом;
  - фильтр «Это устройство» показывает только свои прослушивания.
- Тестовые аккаунты после проверки удалить (`POST /auth/me/delete`).
