# Тексты песен через сервер: задание для Windows-клиента

Дополнение к `docs/PROMPT.md`. Работай по нему параллельно с сессией на Mac: она делает серверную часть и Android. Контракт ниже уже решён. Не меняй его. Если чего-то не хватает, скажи пользователю.

## 1. Что нужно пользователю

Пользователь нашёл текст трека, синхронизировал его в редакторе Android — и хочет, чтобы:
- текст сохранился на сервере и появился на всех его устройствах, включая Windows;
- другие пользователи сервера получили этот текст, если у них для трека нет своего синхронного текста. Это как SponsorBlock, только для текстов.

## 2. Контракт сервера (melogoldServer `docs/API.md` §4.10)

Сервер объявляет модуль в `GET /server/info`: `features.lyrics = {version: 1}`. Без этого ключа клиент к маршрутам текстов не обращается.

| Метод | Путь | Ответ | Что делает |
|---|---|---|---|
| GET | `/lyrics/{videoId}` | 200 `LyricsResponse` | своя версия и общая версия трека |
| PUT | `/lyrics/{videoId}` | 200 `MyLyrics` | сохранить свою версию |
| DELETE | `/lyrics/{videoId}` | 204 | удалить свою версию (надгробие) |
| POST | `/auth/me/lyrics/changes` | 200 `MyLyricsPage` | свои версии, изменённые после `after` |

Все маршруты — с Bearer. Заголовок `X-Sync-Protocol` не нужен.

```ts
type LyricsText = {
  plain: string | null;          // обычный текст, ≤50 000
  plainSource: string | null;    // user|file|youtube_music|lrclib|kugou
  synced: string | null;         // синхронный текст, ≤200 000
  syncedFormat: string | null;   // lrc|ttml; есть вместе с synced
  syncedSource: string | null;
  startTimeMs: number | null;    // где в треке начинается синхронный текст
  language: string | null;       // BCP 47
};
type LyricsPut = {               // все поля можно опустить; нужен plain или synced
  plain?: string; plainSource?: string; synced?: string; syncedFormat?: string;
  syncedSource?: string; startTimeMs?: number; language?: string;
};
type MyLyrics = { id: Uuid; videoId: VideoId; rev: number; deleted: boolean; text: LyricsText | null; updatedAt: Iso };
type SharedLyrics = { id: Uuid; videoId: VideoId; text: LyricsText; updatedAt: Iso };
type LyricsResponse = { mine: MyLyrics | null; shared: SharedLyrics | null; serverTime: Iso };
type LyricsChangesRequest = { after: number; limit?: number /*1..200, по умолчанию 100*/ };
type MyLyricsPage = { items: MyLyrics[]; rev: number; more: boolean };
```

**PUT:**
- нужен хотя бы один из `plain` и `synced`, иначе `400 invalid_request`;
- `syncedFormat` обязателен вместе с `synced` и запрещён без него;
- источник без текста своей стороны сервер отбрасывает;
- если содержимое не изменилось, `rev` не растёт и события нет;
- иначе `rev` = max(`rev` пользователя) + 1, и другие устройства получают SSE `lyrics.changed {videoId, rev}` (склейка 2 с).

**DELETE** ставит надгробие: `deleted: true`, `text: null`, `rev` растёт, приходит то же событие.

**GET `shared`** — версия другого пользователя: сначала с синхронным текстом, затем только с обычным, среди них самая свежая. Автор не раскрывается.

**`/auth/me/lyrics/changes`:**
- отдаёт свои версии с `rev > after` по возрастанию;
- при `after = 0` надгробий нет, это первая загрузка;
- `rev` ответа — это `after` для следующего запроса; пока `more: true`, запрашивай дальше.

**Лимиты:** тело PUT ≤ 1 МиБ, `language` ≤ 35. **Частота:** PUT и DELETE — 60/мин, остальные — 120/мин.

## 3. Что сделать в клиенте

Так же сделает и Android, чтобы клиенты вели себя одинаково.

1. **Локальные данные.**
   - Текст трека: обычный и синхронный, их источники, `startTimeMs`, язык.
   - Источники локально: `user`, `file`, `youtube_music`, `lrclib`, `kugou`, `melogold` (общий текст с сервера).
   - Снимок того, что сервер знает о своих версиях: `synced_lyrics(videoId, rev, hash)` и ключ состояния `lyricsRev`.
   - При смене аккаунта или сервера снимок и `lyricsRev` забываются, как снимок библиотеки.
2. **Свой текст** — строка, у которой хотя бы одна сторона с источником `user` или `file`:
   - импорт `.lrc` в окне «Найти другой текст» даёт `file`;
   - редактор текстов появится позже, он даст `user`.
   - Выбор готового результата LrcLib своим текстом не считается и на сервер не уходит.
3. **Цикл синхронизации текстов** — внутри общего цикла синка, после библиотеки:
   1. отправка: свой текст, которого нет в снимке или чей хэш изменился, → `PUT`; строка снимка, у которой больше нет своего текста, → `DELETE`. Хэш — SHA-256 полей из `LyricsPut`;
   2. загрузка: `POST /auth/me/lyrics/changes` с `after = lyricsRev`, пока `more: true`;
      - версия → записать локально с источниками как есть (своя версия остаётся своей) и обновить снимок;
      - надгробие → удалить локальный свой текст, только если он не менялся с прошлого синка (хэш равен снимку). Иначе оставить: он уйдёт на сервер следующей отправкой;
      - в конце сохранить `lyricsRev` из ответа;
   3. конфликт: побеждает последний `PUT`, как у библиотеки.
4. **Когда запускать:**
   - те же поводы, что у синка библиотеки;
   - SSE `lyrics.changed` → цикл;
   - через 2 с после того, как пользователь сохранил свой текст.
5. **Общие тексты в цепочке поиска.**
   - Если провайдеры не нашли синхронный текст и пользователь вошёл в аккаунт на сервере с `features.lyrics`, запроси `GET /lyrics/{videoId}`:
     - `mine` есть (ещё не пришёл синком) → показать и сохранить как свой;
     - иначе есть `shared` → показать и сохранить с источником `melogold`. Такой текст никогда не отправляется как свой.
   - Подпись под текстом: «Текст: сообщество Melogold».
6. **Форматы.**
   - `syncedFormat: lrc` — LRC и расширенный LRC.
   - `syncedFormat: ttml` — TTML с пословной разметкой, сторонами исполнителей (дуэты) и бэк-вокалом: так сохраняет редактор Android.
   - Разбор обоих форматов — по melogoldAndroid `docs/spec/lyrics.md` и `docs/spec/lyrics.vectors.json`.
   - Windows обязан показывать TTML от Android-пользователей. Если модели текста для него пока нет, это часть задачи.
7. **Ошибки и сеть.**
   - Нет сети — ничего не делать, следующий цикл повторит.
   - `413` — текст слишком большой: не отправлять и сказать пользователю.
   - `401` и прочее — общая обработка сессии.

## 4. Проверка

- **Юнит-тесты:** разница со снимком (новая версия, изменённая, удалённая, надгробие поверх неизменённой и изменённой строки), разбор ответов.
- **Сквозная проверка на живом сервере** после выкладки модуля (сессия на Mac сообщит; готовность видна по `features.lyrics` в `/server/info`):
  - текст, сохранённый на Android, появляется в Windows за секунды, и наоборот (импорт `.lrc` в Windows виден на Android);
  - удаление на одном устройстве убирает текст на другом;
  - второй аккаунт без своего текста видит общий с подписью «сообщество Melogold».
- Тестовые аккаунты после проверки удалить (`POST /auth/me/delete`).
