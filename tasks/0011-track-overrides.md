# Своё название, исполнитель и альбом трека

Статус: открыто — ждёт сервер (`melogoldServer/tasks/0001-track-overrides.md`: контракт ещё не утверждён)

Те же задания: `melogoldAndroid/tasks/0012-track-overrides.md`, `melogoldiOSmacOS/tasks/0014-track-overrides.md`,
`melogoldLinux/tasks/0005-track-overrides.md`.

## 1. Что нужно пользователю

Melogold — обход цензуры в музыке. Альбом, который зацензурировали, а потом удалили, лежит на YouTube разными видео:
«Artist — Song (live, fan upload)», канал вместо исполнителя, альбома нет. Пользователь собирает эти треки в плейлист
(действия с выделенным, Windows 0.1.10) и хочет, чтобы они выглядели одним альбомом на всех его устройствах.

Решение пользователя (2026-09-26): **только текст** — название, исполнитель, альбом; синхронизируется через сервер.
Обложки и файлы не храним (у сервера 30 ГБ).

## 2. Как должно быть (одинаково на всех клиентах)

- **Меню трека → «Изменить сведения…»** (Edit details…): окно «Сведения о треке» (Track details) с полями «Название»,
  «Исполнитель», «Альбом» (Title, Artist, Album). В пустом поле серым — как на YouTube. Кнопки: «Сохранить», «Как на
  YouTube» (снять всю правку), «Отмена».
- **Выделенное → «Указать альбом…»** (Set album…): одно поле, альбом ставится всем выделенным; по умолчанию — общий
  альбом выделенного, если он один, иначе название плейлиста, из которого выделяли. Плашка «Альбом указан: {0}».
- **Где действует правка** — везде, где показан трек: строки, панель плеера, «Сейчас играет», мини-плеер, очередь,
  системные медиаэлементы (SMTC / MPRIS / экран блокировки), теги «Сохранить файлом», поиск по библиотеке (находит и по
  правленому, и по оригинальному названию).
- **Поиск текста песни** спрашивает сначала по правленым названию и исполнителю, потом по оригиналу: у загрузок фанатов
  LrcLib по оригинальному «Artist — Song (live, fan upload)» не находит, а по правленому — находит.
- **Синк:** op `track.override.set` (замена целиком: пустое поле — без правки; все пустые — правка снята), в ответе —
  `overrides`. Отправляется, только если сервер перечисляет этот вид в `features.sync.kinds`; иначе правка живёт на
  устройстве и уходит, когда сервер научится.
- **Копия библиотеки** (импорт/экспорт) переносит правки — добавить поле в общий формат копии (сверить с Android
  `docs/spec`).
- Тексты интерфейса — сверить с `melogoldAndroid/docs/GLOSSARY.md`.

## 3. Windows

- `Melogold.Core/Data`: схема v7 — `track_overrides(video_id PK, title, artists_text, album_title, updated_at)` и
  метка «не отправлено»; `LibraryChange.Overrides`.
- Показ: одна точка применения правки к `Track` (например, `Library.Display(track)`), которую зовут `RowVm`,
  `PlayerViewModel`, `NowPlayingView`, `MiniPlayerWindow`, `PlayerEngine.ApplyDisplayProperties` (SMTC),
  `FileExport` (теги), `LyricsService` (запрос к LrcLib).
- `Melogold.Server/LibrarySync`: отправка op и разбор `overrides` (как `likes`), `include.overrides`.
- Меню — `TrackActions.AddItems`, выделенное — `SelectionBar` и `TrackActions.BuildSelectionMenu`.

## 4. Проверка

- Юнит-тесты: применение правки (пустое поле → оригинал), поиск по обоим названиям, op «замена целиком», разбор
  `overrides`.
- Живой сервер (после серверного задания, временный аккаунт): правка на одном «устройстве» приходит на другое;
  лайк с оригинальными метаданными правку не сбрасывает.
- Снимки: окно «Сведения о треке», плейлист из разрозненных видео с одним альбомом.
