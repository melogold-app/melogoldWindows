# Устройства Apple в аккаунте: значки и одобрение входа по коду

Статус: открыто

Появляется клиент Melogold для Apple: iPhone, iPad, Mac, Vision Pro и самостоятельное приложение для Apple Watch (`melogoldiOSmacOS`). Его устройства входят в тот же аккаунт и видны в списке устройств Windows. Значения `platform` — в API §1.6 сервера (коммиты 651b1a7 и 90f5149): `ios`, `ipados`, `macos`, `visionos`, `watchos`.

## 1. Значки устройств (минимум, сделать первым)

Сейчас `AccountPages.cs` рисует телефон (`E8EA`) только для `android` и `ios`, а всё остальное — компьютером (`E977`). iPad, Vision Pro и часы выглядят компьютерами.

Одна функция `platform → глиф` на всё приложение, по примеру `DeviceSymbol` Clementine: список устройств, фильтр «Устройство» в Истории (задание 0002), карточка одобрения входа (раздел 2).

| `platform` | Значок (Segoe Fluent Icons) | Подпись для экранного диктора |
|---|---|---|
| `android`, `ios` | телефон, `E8EA` | «Телефон» |
| `ipados` | планшет, `E70A` | «Планшет» |
| `macos`, `windows`, `linux` | компьютер, `E977` | «Компьютер» |
| `watchos` | часы — подбери ближайший глиф в Segoe Fluent Icons | «Часы» |
| `visionos` | гарнитура или смешанная реальность — подбери ближайший глиф | «Гарнитура» |
| любое другое | компьютер, `E977` | «Устройство» |

Сравнение — по точному значению `platform`, в нижнем регистре. Незнакомое значение не ломает список.

## 2. «Добавить устройство»: одобрить вход по коду (нужно часам)

На часах неудобно набирать пароль. Поэтому часы умеют входить по коду (API §4.6, режим `request`):
1. Часы показывают код вида `K7QX-M2PD`.
2. Любое устройство, где уже выполнен вход, вводит этот код.
3. Затем оно выбирает число, которое видно на часах.

Сейчас одобрять умеют только устройства Apple. Если у пользователя кроме часов только Windows, часам придётся вводить пароль. Нужно, чтобы одобрять умел и Windows.

- **Аккаунт:** кнопка «Добавить устройство».
- **Диалог:**
  1. Поле кода `XXXX-XXXX`. Ввод нормализуется по API §1.6 `UserCode`: верхний регистр, пробелы и `-` удалить, `O→0`, `I,L→1`.
  2. `POST /auth/me/links/resolve {"userCode": …}` возвращает `LinkDetails`.
  3. Карточка устройства: значок по разделу 1, имя, модель и версия системы, подсказка «в той же сети» или «в другой сети» (`sameNetwork`, если не `null`), время до истечения.
  4. «Выберите число, которое видно на новом устройстве» — три кнопки из `verifyChoices`, и «Отклонить».
  5. Выбор числа — `POST /auth/me/links/{id}/approve {"verifyCode": …}`; «Отклонить» — `…/deny {}`.
- **Итог:** «„Apple Watch“ вошло в аккаунт», список устройств обновляется.
- **Ошибки** (API §2.2):
  - `link_not_found` → «Код не найден»;
  - `link_expired` → «Код устарел — запросите новый на устройстве»;
  - `link_verify_mismatch` → «Число не совпало — вход отклонён»;
  - `link_already_claimed` → «Этот код уже используется»;
  - `link_wrong_mode` → «Это код приглашения, а не входа»;
  - `device_limit_reached` → открыть список устройств.
- **Тексты** — в `ru-RU` и `en-US`.

## 3. Проверка

- Юнит-тест функции значков: все значения из таблицы и незнакомое.
- Нормализация `UserCode` на векторах вроде `k7qx m2pd`, `K7QX-M2PD`, `k7qxm2pd` и с буквами `O`, `I`, `L`.
- Скриншот списка устройств. Пока Apple-клиента нет, устройства iPhone, iPad и часов для проверки можно создать запросом `POST /auth/login` с `platform` = `ios`, `ipados`, `watchos` на локальном сервере.
