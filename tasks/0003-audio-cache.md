# Кэш музыки 4 ГБ и «есть без сети»

Статус: открыто

То же задание есть в `melogoldAndroid/tasks/0001-audio-cache.md`, Android делается параллельно.

## 1. Что нужно пользователю

- Проигранная музыка всегда остаётся в кэше: повторное прослушивание не тратит трафик и запросы к YouTube.
- Кэш по умолчанию 4 ГБ. Когда он заполнен, место освобождают треки, которые дольше всех не слушали.
- Полностью закэшированный трек играет без сети и без запроса потока.
- Такие треки видно как доступные без сети.

## 2. Решение (одинаково на всех клиентах)

У трека три состояния:

| Состояние | Что это | Как видно |
|---|---|---|
| Скачан | пользователь нажал «Скачать»; хранится отдельно и из кэша не вытесняется | заполненный значок «скачано», раздел «Скачанное» |
| В кэше | проигран целиком и лежит в кэше; может смениться новыми треками | контурный значок того же вида, приглушённый; раздел «Скачанное», группа «В кэше» |
| Нет | — | — |

Почему кэш не называется «скачано»:
- кэш вытесняется, и трек с меткой «скачано» мог бы пропасть перед поездкой без сети;
- ViTune на этом обжёгся: его загрузки жили в вытесняемом кэше и пропадали (VT#1057, #1476);
- отдельная метка честно говорит «сейчас есть без сети», а «Скачать» у такого трека срабатывает сразу и без сети: байты берутся из кэша.

**«Скачанное»:**
- сверху скачанные;
- ниже группа «В кэше · N · X МБ» с пояснением «Играют без сети, пока их не сменят новые треки».

**Без сети:** треки, которых нет ни в загрузках, ни целиком в кэше, приглушены. Нажатие по такому треку показывает «Нет сети».

## 3. Правила кэша

- **Ключ** — `videoId`: адрес потока меняется, ключ нет. В кэше лежит один формат (itag); если формат сменился, старые байты трека удаляются.
- **Кэшируется всё, что играет**, куски пишутся по мере чтения. «Целиком в кэше» — есть все байты от 0 до `contentLength`.
- **Вытеснение** — по времени последнего чтения: сначала то, что дольше всех не слушали. Играющий трек не вытесняется.
- **Размер:**
  - «Хранилище → Размер кэша»: 32 МБ … 8 ГБ и «Без ограничений», по умолчанию **4 ГБ**;
  - там же «занято X из Y» и «Очистить кэш»;
  - если пользователь раньше сам не выбирал размер, новое значение по умолчанию действует и для него.
- **Трек целиком в кэше играет без запросов:** ни InnerTube `player`, ни поиска адреса, включая последний, неполный кусок файла.
- **«Скачать» у трека «в кэше»** копирует байты из кэша в загрузки, сеть не нужна.
- Кэш не синхронизируется и не входит в резервные копии.

## 4. Windows

- Сейчас кэш — `SongCache` (`%LOCALAPPDATA%\Melogold\cache\songs`), а `SettingsStore.SongCacheMaxMb` по умолчанию 2048. Приведи его к правилам выше:
  - по умолчанию 4096;
  - индекс треков: `videoId`, `itag`, `contentLength`, сколько байт есть, время последнего чтения;
  - вытеснение по индексу, без обхода диска при каждом чтении.
- Источник потока для `MediaPlayer` (свой поток поверх HTTP Range) читает сначала из `SongCache`. Недостающие куски берёт из сети и сразу пишет в кэш.
- Если трек целиком в кэше, адрес потока не резолвится вовсе.
- **Метки в строках:** рядом с длительностью — контурный значок «есть без сети» (Segoe Fluent Icons) для «в кэше» и заполненный для «скачано», с подсказкой и именем для экранного диктора.
- **«Скачанное»:** загрузок у Windows пока нет (0.2 по `docs/PROMPT.md`), поэтому страница пока показывает только группу «В кэше». Когда появятся загрузки, «Скачать» у трека в кэше копирует файл из кэша.
- **Без сети:** строки треков не в кэше приглушены, двойной клик по ним — `InfoBar` «Нет сети».

## 5. Проверка

- Юнит-тесты индекса:
  - вытеснение по давности;
  - играющий трек не вытесняется;
  - «целиком в кэше» по `contentLength`, в том числе при неполном последнем куске;
  - смена формата удаляет старые байты.
- Трек, прослушанный до конца, при повторе играет с выключенной сетью. В логе нет запросов `player` и потока.
- При лимите 32 МБ старые треки уходят, новые пишутся, играющий не трогается.
