# Melogold для Windows: задание для Claude

Этот файл — задание для сессии Claude, которая пишет Windows-клиент. Прочитай его целиком и работай по нему. Если часть проекта уже сделана иначе, сверь её с документом и покажи расхождения пользователю, прежде чем переделывать.

## 1. Что такое Melogold

- Клиент YouTube Music и обычного YouTube с общей библиотекой на всех устройствах. Начинался как форк ViTune (Android).
- Главный смысл: треки, которые в России вырезали из Apple Music, есть на YouTube (часто перезаливами). Поэтому обычный YouTube — такой же источник, как каталог YouTube Music: видео ищутся, играют, лежат в плейлистах и очереди наравне с песнями.
- Работает без аккаунта. По желанию пользователь входит на сервер Melogold (логин и пароль), и избранное, плейлисты, сохранённые альбомы и исполнители синхронизируются между устройствами. Сервер хранит только метаданные (`videoId` и т. п.). Звук каждый клиент берёт с YouTube сам.
- Части (все репозитории публичные, организация `melogold-app`):
  - `melogoldAndroid` — Kotlin, Material 3 Expressive, выпущен 0.1.1. Эталон поведения и спецификаций;
  - `melogoldServer` — TypeScript/Node, контракт API;
  - `melogoldWindows` — этот репозиторий;
  - Linux и macOS — позже.
- Рабочий сервер: `https://178-250-187-202.sslip.io`, регистрация открыта. Скоро у него будет нормальный домен, старый адрес продолжит работать. Адрес сервера по умолчанию — константа сборки.
- Иконка: `Assets/melogold.ico` (белая плитка). Генератор всех иконок — `melogoldAndroid/branding/icon/build.py`.

## 2. Как работает пользователь

- Пишет по-русски. Интерфейс приложения — русский и английский.
- Работай сам и последовательно, по срезам. Срез: сборка и тесты → запуск → скриншот → коммит → push → показать результат. Субагенты и параллельные воркфлоу — только по просьбе пользователя.
- Коммиты — conventional на русском (`feat: …`, `fix: …`, `docs: …`), в конце строка `Co-Authored-By: Claude …`.
- Держи `main` рабочим и сливай в него часто: пользователь хочет видеть прогресс, а не ветки, которые не вливаются.
- Следуй официальным гайдлайнам платформы строго: для Windows это Fluent 2 и документация WinUI 3 «Design and code Windows apps». Выбирай простоту и единообразие. Нестандартное и декоративное пользователь воспринимает как мусор.
- Если пользователь отверг элемент интерфейса, убери его отовсюду, включая вложенные экраны.
- Если поведение ещё не решено, спроси, потом делай. Решённое не переспрашивай.
- Не поднимай несрочные юридические вопросы, покупки (домены, сертификаты подписи кода) и админские дела. Продолжай строить.
- Пароли пользователя не спрашивай, не вводи и не храни. Секреты (ключи, пароли подписи) держи вне репозитория.
- Контракт сервера сам не меняй. Если клиенту что-то нужно от сервера, опиши это и скажи пользователю.

## 3. Стек и устройство (решено)

- **Платформа:**
  - C#, .NET 10 (LTS; поддержка .NET 8 кончается в ноябре 2026);
  - WinUI 3 на актуальном стабильном Windows App SDK (у Clementine — 1.8).
- **Упаковка:**
  - без MSIX: `WindowsPackageType=None`, `WindowsAppSDKSelfContained=true`, self-contained .NET;
  - сборки x64 и ARM64;
  - минимальная Windows 10 2004 (`10.0.19041.0`). Mica — только на Windows 11, на Windows 10 запасной фон.
- **Образец:** Windows-клиент Clementine VPN того же пользователя (`windowsClementine`, если он есть на этом компьютере). Там WinUI 3, установщик Inno Setup, `UpdateService` с проверкой SHA-256, сессия под DPAPI, один экземпляр, `LocalizationService`. Бери оттуда приёмы, VPN-специфику не переноси.
- **Проекты:**
  - `Melogold.Core` — чистые правила без WinUI, порт `:core:domain` и `providers/*` Android: TitleCleaner, ServerAddressPolicy, YouTubeLinkParser, модель текстов и LRC, PlaylistDiff, правила очереди;
  - `Melogold.InnerTube` — клиент YouTube Music и YouTube, порт `providers/innertube`;
  - `Melogold.Server` — API сервера Melogold и синк;
  - `Melogold.Playback` — извлечение потока и плеер;
  - `Melogold.App` — WinUI 3: окна, страницы, ViewModel на CommunityToolkit.Mvvm, DI на Microsoft.Extensions.DependencyInjection;
  - `Melogold.Tests` — xUnit.
- **Данные:**
  - SQLite через Microsoft.Data.Sqlite; база, кэш и логи — в `%LOCALAPPDATA%\Melogold\`;
  - схема идёт от модели сервера: трек по `videoId`, плейлист с `syncId`, позиция трека в плейлисте с `sortKey`, лайки, закладки альбомов и исполнителей;
  - только локально: история, очередь, кэш.
- **Сеть:** один `SocketsHttpHandler`. У каждого потребителя свой User-Agent, глобального нет:
  - InnerTube WEB и WEB_REMIX — браузерный UA своего клиента, как в `providers/innertube/.../models/Context.kt`;
  - сервер Melogold — `melogold-windows/<semver>` (API §1.2);
  - lrclib и kugou — `Melogold/<версия> (+https://github.com/melogold-app/melogoldWindows)`;
  - googlevideo — заголовки, которые вернул экстрактор.
- **Сессия:**
  - токены лежат под DPAPI, а не открытым текстом в настройках;
  - `hwid` — по API §1.6: `MachineGuid|installSalt`, векторы `spec/hwid.vectors.json` в `melogoldServer`.
- **Логи:**
  - файл до 2 МБ; при старте он переименовывается в `previous`;
  - последнее падение пишется в отдельный файл;
  - «Диагностика» открывает папку с логами.
- **Один экземпляр:** второй запуск активирует окно и передаёт ему аргументы — ссылки `melogold://` и YouTube.
- **Установщик:**
  - Inno Setup без прав администратора: `PrivilegesRequired=lowest`, папка `%LOCALAPPDATA%\Programs\Melogold`;
  - ярлык в «Пуске», протокол `melogold://` в HKCU;
  - удаление не трогает данные пользователя без явного флажка.
- **Обновления** — как на Android и в Clementine:
  - источник: `https://github.com/melogold-app/melogoldWindows/releases/latest/download/update.json` (без лимитов API GitHub);
  - формат как у Android (`version`, `notes` с ключами `ru` и `en`, `publishedAt`) плюс файлы по архитектурам: `"assets": {"x64": {"fileName", "sizeBytes", "sha256"}, "arm64": {…}}`;
  - проверка при старте не чаще раза в 6 часов и по кнопке «Проверить обновления»;
  - когда есть обновление: карточка «Вышла новая версия» вверху Настроек и `InfoBadge` с цифрой 1 на пункте «Настройки»;
  - установка: загрузка с прогрессом → проверка размера и SHA-256 → тихий запуск установщика (`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`) → приложение закрывается, установщик запускает его снова;
  - релиз собирает `scripts/release.ps1`: обе архитектуры, `update.json`, затем `gh release create vX.Y.Z --latest`;
  - версия задаётся в одном месте (`Directory.Build.props`), без суффиксов вроде `-RELEASE`;
  - подписи кода нет, SmartScreen предупредит при первой установке. Это известно и не блокер.
- **CI:** GitHub Actions на `windows-latest` — сборка x64 и ARM64 и тесты на каждый push.

## 4. Воспроизведение (решено, с учётом граблей Android)

- **Поток:**
  - всё на C#, без Python и yt-dlp (решение пользователя от 25.09.2026): запрос InnerTube `player` клиентами, которые отдают прямые ссылки без расшифровки подписи, — сейчас IOS, затем ANDROID_VR (`Melogold.InnerTube/Player.cs`, `Melogold.Playback/StreamResolver.cs`);
  - список клиентов (имя, версия, User-Agent) — JSON в этом репозитории: приложение подтягивает свежий, встроенный остаётся запасным. Так поломку на стороне YouTube можно чинить без релиза;
  - если YouTube закроет все такие клиенты — вторая линия: расшифровка WEB-клиента на встроенном JS-движке Jint (тоже C#). В 0.1 не делается.
- **Формат:** сначала itag 140 (AAC в m4a). Opus 251 — только если система его декодирует.
- **Скорость старта:** медиана от нажатия до звука не больше 3 с на Wi‑Fi, p90 — не больше 6 с. Для этого:
  - адреса двух следующих треков резолвятся заранее;
  - сторож на извлечение — 20 с;
  - одновременно не больше двух извлечений.
- **Плеер:**
  - `Windows.Media.Playback.MediaPlayer`: он даёт SystemMediaTransportControls (медиаклавиши, системная плашка Windows), скорость воспроизведения и бесшовный переход через `MediaPlaybackList`;
  - источник — свой поток поверх HTTP Range кусками, как `ChunkedYouTubeDataSource` в Android `service/PlayerService.kt`. Так плеер переживает 403 и истечение адреса.
- **Ошибки** — по REWRITE §4.10.3 Android, с теми же текстами:
  - 403 от googlevideo — не пропуск: сбросить адрес в кэше, получить новый и повторить, до двух раз;
  - кэш адресов: LRU на 64 записи, срок — параметр `expire` минус 5 минут, сброс при смене сети (`NetworkInformation.NetworkStatusChanged`);
  - повторы: сеть — 2 (через 1 с и 3 с), таймаут — 1, проверка на бота — 1 с другим набором клиентов;
  - гео-блок, «видео недоступно» и возрастное ограничение — сразу пропуск с понятной причиной;
  - после трёх пропусков подряд воспроизведение останавливается.
- **Громкость и скорость:**
  - нормализация громкости — по `loudnessDb`;
  - скорость 0,5–2× — одна глобальная настройка в «Настройки › Воспроизведение». В меню плеера её нет.
- **Столбики «играет»** двигаются под реальный звук (низы, середина, верх), а не по кругу. На Android это `TeeAudioProcessor` (`service/AudioLevels.kt`).
  - Для MediaPlayer — свой `IBasicAudioEffect`, зарегистрированный без MSIX через манифест приложения.
  - Если за день не заводится — захват звука своего процесса (process loopback, Windows 11), а где его нет — спокойные столбики.
  - Скажи пользователю, какой вариант получился.
- **Очередь** — по REWRITE §2.3 и §4.10.4:
  - тап по треку в списке играет список, по одиночному треку — трек и радио;
  - «Играть следующим» и «В конец очереди»;
  - при замене очереди — «Очередь заменена · Отменить»;
  - в конце очереди — автоплей похожих без повторов;
  - перемешивание; повтор: выкл · все · один;
  - после перезапуска очередь и позиция восстанавливаются, без автостарта.
- **Таймер сна:** 15, 30, 45 или 60 минут и «До конца трека».

## 5. Дизайн

Цель — нативное приложение Windows 11 уровня встроенных «Медиаплеера» и Microsoft Store: Fluent 2, стандартные контролы WinUI 3, системный шрифт, акцентный цвет Windows. Вид Android (M3E) не переносится. От Android берутся разделы, поведение и тексты, но не оформление.

### 5.1 Окно и навигация

- Mica (на Windows 10 запасной фон) и своя строка заголовка (`TitleBar`): «Назад», иконка, «Melogold», поле поиска по центру.
- `NavigationView` слева, `PaneDisplayMode=Auto`: в широком окне — панель с подписями, в среднем — только иконки, в узком — меню-гамбургер.
- **Пункты:**
  - Тренды · Новое · Библиотека;
  - «Настройки» — внизу панели, стандартным пунктом WinUI;
  - поиск — поле в заголовке (Ctrl+F или «/»). Это Windows-аналог вкладки «Поиск».
- На Android порядок решён пользователем: Тренды · Новое · Библиотека · Поиск · Настройки. Здесь он сохранён. Если пользователь захочет «Поиск» пунктом в панели, добавь его четвёртым.
- Приложение открывается в разделе, где пользователь был при выходе. При первом запуске — «Тренды».
- Детальные экраны (альбом, исполнитель, плейлист, выдача поиска) открываются в стеке текущего раздела. Панель и плеер остаются на месте.
- «Назад» — кнопка, Esc, Alt+← или боковая кнопка мыши. Порядок:
  1. закрыть меню и диалоги;
  2. закрыть «Сейчас играет»;
  3. шаг назад в стеке раздела;
  4. в корне нестартового раздела — перейти на «Тренды».
- Повторное нажатие на активный раздел: во вложенном экране возвращает к корню, в корне прокручивает наверх.
- Вертикальных надписей и нестандартных реек нет: повёрнутую рейку ViTune пользователь отверг.

### 5.2 Плеер

- **Панель воспроизведения** — внизу во всю ширину окна, как в «Медиаплеере»:
  - слева: обложка 56 px, название, исполнитель и ♡. Клик по обложке открывает «Сейчас играет», по названию — альбом, по исполнителю — исполнителя;
  - в центре: ⇄ ⏮ ⏯ ⏭ ⟲ и ползунок перемотки со временем;
  - справа: «Текст», «Очередь», громкость, мини-плеер и «…» — одно меню на всё, как на Android (REWRITE §3.10.5): играющий трек теми же пунктами, что в списках (без «Играть следующим», «В конец очереди» и ♡ — он рядом), меню текста, пока текст на экране, таймер сна, сведения о потоке и в конце «Не показывать этот трек» (трек пропускается);
  - по ширине окна панель перестраивается, а спрятанное уходит в начало «…» с сочетаниями клавиш справа (пользователь, 2026-09-26: «оптимизация под разные размеры окна»):
    - от 1100 — всё;
    - от 860 — без ползунка громкости (громкость — колесом над кнопкой звука);
    - от 720 — без кнопки звука и мини-плеера;
    - уже 720 — две строки, как «Медиаплеер» Windows: перемотка сверху во всю ширину, под ней трек, ⏮ ⏯ ⏭, «Текст», «Очередь», «…»; ♡, перемешать и повтор — в «…»;
  - боковые колонки панели всегда равной ширины: Play посередине окна.
- **Размер окна:** не меньше 500×500 эффективных пикселей (пересчёт при смене масштаба экрана). В узком окне: поиск в заголовке без подписи «Melogold»; шапка коллекции — обложка 160 сверху, текст под ней; карточки Библиотеки и поля страниц — по ширине, поля 16 вместо 36.
- **Пока нет потока:** кнопка play показывает `ProgressRing`, через 3 с появляется подпись «Получаем поток…». При ошибке — причина словами и «Повторить».
- **«Сейчас играет»** — страница поверх окна, Esc закрывает её:
  - фон — мягкий оттенок по цвету обложки (Material Color Utilities, как на Android; есть порт на C#);
  - размытой обложки нет: это граница с Apple Music (REDESIGN §5.5);
  - в широком окне обложка слева, синхронный текст справа. В узком — переключатель «Обложка · Текст».
- **Синхронный текст** (Android `ui/screens/player/modern/SyncedLyricsView.kt`, REDESIGN §5.1):
  - активную строку отмечает подложка, которая переезжает на пружине; прошедшие строки приглушены сильнее будущих;
  - клик по строке перематывает;
  - ручная прокрутка останавливает слежение на 3 с, есть кнопка «К текущей строке»;
  - в паузе без слов точки появляются только на время паузы: выскакивают по одной и лопаются перед следующей строкой. Пользователь просил именно так — игриво, как в Apple Music;
  - если синхронного текста нет, показывается обычный.
- **Меню текста** — группа в «…» панели плеера, своей кнопки «…» у текста нет:
  - переключатель синхронного и обычного текста подписан по тому, что сейчас на экране, а не по настройке;
  - «Найти другой текст» — поиск по LrcLib с импортом файла `.lrc`;
  - «Сдвиг текста» — подменю: ±0,1 и ±0,5 с.
- **Очередь** — панель справа, около 320 px:
  - перетаскивание; удаление крестиком при наведении или клавишей Delete;
  - блок автоплея под заголовком «Далее — похожие»;
  - «Сохранить как плейлист», «Очистить».
- **Мини-плеер** — отдельное окно поверх остальных (`CompactOverlay`): обложка, название, ⏮ ⏯ ⏭.
- **Система:** SMTC (медиаклавиши, плашка Windows с обложкой) и кнопки ⏮ ⏯ ⏭ на миниатюре в панели задач.

### 5.3 Списки и строки

- **Строка трека** — около 56 px:
  - обложка 40 px, при наведении на ней кнопка play;
  - название, под ним исполнитель и альбом, справа длительность;
  - ♡ и «…» видны при наведении и на строке с фокусом.
- Двойной клик или Enter играет, одиночный клик выделяет — как принято в Windows.
- Правый клик или «…» открывает `MenuFlyout`. Пункты — как в меню трека Android (`ui/components/menu/MediaItemMenu.kt`), так же коротко:
  - «Играть следующим», «В конец очереди», «Добавить в плейлист…», «Скачать» (или «Скачивается 45 % · Отменить», «Удалить загрузку»), «Сохранить файлом»;
  - «Радио по треку»;
  - «В избранное» или «Убрать из избранного»;
  - «Перейти к альбому», «Перейти к исполнителю» (подменю, если исполнителей несколько);
  - «Другие версии», «Скопировать ссылку», «Поделиться»;
  - «Убрать из плейлиста» (истории, очереди), «Не показывать».
- Меню Android пользователь однажды уже назвал громоздким. Лишних пунктов не добавляй.
- У видео квадратные обложки, как у песен. Видео и песни — равные источники везде: в поиске, строках, очереди.
- Порядок в своём плейлисте меняется перетаскиванием, с клавиатуры — Alt+↑ и Alt+↓.
- В длинных списках есть фильтр и сортировка, сортировка запоминается.
- Мультивыбора в 0.1 нет.

### 5.4 Экраны

Содержимое экранов описано в Android REWRITE §3.1–§3.9, вид — по Fluent.

- **Поиск:**
  - до ввода — недавние запросы; при вводе — подсказки и «В библиотеке»;
  - вставленная ссылка YouTube открывает свою цель (REWRITE §2.3, `youtube-links.vectors.json`);
  - выдача: `SelectorBar` «Всё · Музыка · YouTube». В «Музыке» — Песни, Альбомы, Исполнители, Клипы, Плейлисты. В «YouTube» — Видео, Каналы, Трансляции, Плейлисты.
- **Тренды:** «В тренде», «Настроения и жанры».
- **Новое:** новые альбомы и синглы, «Для вас», похожие исполнители и альбомы.
- **Библиотека** — хаб коллекций:

### 5.5 Состояния, отмена, доступность

- **Четыре состояния** у каждого экрана:
  - загрузка — `ProgressRing` по центру видимой области, появляется через 300 мс; скелетонов нет;
  - контент;
  - пусто — иконка, заголовок, одна строка пояснения и 1–3 кнопки;
  - ошибка — тексты из REWRITE §3.0 дословно (Offline, Blocked, Parser, Unknown) и кнопка «Повторить».
- Без сети, но с кэшем — `InfoBar` «Нет сети — данные от 14:02».
- **Отмена:** разрушающее действие выполняется через 5 секунд. Пока идёт отсчёт, над панелью плеера видна плашка «Удалено · Отменить». Плашка одна; новая сразу выполняет предыдущее действие. Плашка всплывает поверх содержимого, как уведомление, и не сжимает окно (пользователь, 2026-09-26).
- **Оформление:**
  - шрифт Segoe UI Variable и его шкала, иконки Segoe Fluent Icons;
  - акцентный цвет Windows, тема по системе;
  - скругления и отступы — токены Fluent.
- **Анимации** — стандартные Fluent, обложка переходит в «Сейчас играет» через `ConnectedAnimation`. Если в Windows выключены эффекты анимации (`UISettings.AnimationsEnabled`), остаются только смены состояний.
- **Клавиатура** (все сочетания — в окне «Сочетания клавиш»: F1 и Ctrl+/, «…» плеера, «Настройки → О приложении»; в подсказках кнопок плеера — их сочетания):
  - Ctrl+F и «/» — поиск; Ctrl+1, 2, 3 — Тренды, Новое, Библиотека; Ctrl+, — настройки;
  - пробел — play/pause, если фокус не в поле ввода;
  - Ctrl+→ и Ctrl+← — следующий и предыдущий трек, Shift+→ и Shift+← — ±5 с, Ctrl+↑ и Ctrl+↓ — громкость, Ctrl+M и M — без звука (пользователь: «все знают, что M — mute»);
  - Ctrl+H — перемешать, Ctrl+T — повтор, Ctrl+D — ♡, Ctrl+L — текст, Ctrl+Q — очередь, Ctrl+Shift+M — мини-плеер;
  - Esc и Alt+← — назад, F11 — «Сейчас играет» на весь экран;
  - в строках: Enter — играть, клавиша меню и Shift+F10 — меню трека, Delete — убрать, Alt+↑ и Alt+↓ — порядок в своём плейлисте;
  - редактор текста, «Синхронизация»: Enter и Shift+Enter — отметка и конец строки, Backspace — отметить последнюю строку заново, ↑ ↓ — какую строку отметить, ← → — ±3 с, [ ] — последняя отметка ±0,1 с;
  - стрелки с Ctrl и Shift в поле ввода остаются полю;
  - клавиши доступа (Alt): разделы, поиск, «…» плеера;
  - фокус идёт по порядку: панель навигации → контент → плеер.
- **Windows:** «Поделиться» в меню трека — системное окно; ссылку или файл копии можно перетащить в окно — ссылка откроется, копия импортируется; правый клик по треку в панели плеера — то же меню, что «…»; колесо мыши над громкостью меняет её; обрезанное название — целиком в подсказке.
- **Доступность:** экранный диктор называет каждую строку и её действия. Поддерживаются режим высокой контрастности и масштаб текста Windows.
- **Тексты** — по Android `docs/GLOSSARY.md`. Слова «Медиатека» и «Слушать» в названиях разделов запрещены.

## 8. Грабли, на которые Android уже наступил

1. **Адрес потока.** 403 от googlevideo и истёкший адрес лечатся повтором со свежим адресом, а не пропуском трека. Ошибка ввода-вывода не должна становиться фатальной.
2. **Синхронный текст** находится, только если искать правильно:
   - у песен (у них есть альбом) сначала timed lyrics YouTube Music через browse клиента ANDROID_MUSIC (`timedLyricsModel`), потом LrcLib, потом KuGou;
   - у видео LrcLib идёт первым;
   - в LrcLib — очищенное название (TitleCleaner), без названия альбома, ближайшая длительность в пределах max(3 с, 10 %).
3. **Картинки.** Для превью до 360 px бери `mqdefault`, а не 1280×720. Картинки грузи параллельно.
4. **Синк:**
   - `base` на каждой op;
   - треки плейлиста меняй мелкими ops: `items.add` с якорем, `item.remove`, `item.move` для треков вне наибольшей возрастающей подпоследовательности;
   - `items.replace` для ручных правок не используй: он стирает то, что другое устройство добавило;
   - сервер отвечает текущими строками всех затронутых ключей;
   - на 410 — один раз заново с пустым курсором.
5. **Каталог.** Плейлисты длиннее 100 треков догружаются продолжениями. Язык контента — `hl` по языку системы (`ru`), а не `en`.
6. **Индикатор загрузки** — по центру видимой области, а не всего окна под плеером.
7. **Меню не дёргается** при открытии: всё, что в нём показывается, известно до открытия.
