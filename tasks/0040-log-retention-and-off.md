# Журнал: выключить совсем и выбрать, сколько хранить; файл на запуск

Статус: сделано — `Melogold.Core`: `LogFiles` (имя файла, новый файл на 2 МБ и с датой, сроки, уборка, удалить всё),
`LogReport` — по списку файлов; `Melogold.App`: `Log.Start(SettingsStore)` применяет «Журнал» и «Хранить» сразу,
`SettingsStore.LogEnabled` и `LogRetentionDays`, «Диагностика» — раскрывающаяся карточка с ними; тесты `LogFilesTests`
и `LogReportTests` на Linux проверены через .NET 10 SDK, журнал приложения прогнан на Linux с настоящим `SettingsStore`;
приложение (WinUI) на Linux не собирается — его проверит CI на Windows после push

Максим (31.10.2026): «сделай, чтобы можно было выбрать, сколько хранятся журналы, и выключить журнал совсем — на всех
платформах». Его ответы: сроки «День · 3 дня · Неделя · Месяц», по умолчанию неделя; при выключении записанное удалить
сразу. Схема общая для клиентов (Linux и Android — по ней же): файлы и тексты должны совпадать.

## Как должно быть

**Настройки** — «О приложении › Диагностика»:
- «Журнал» / "Log", подпись «Записывать работу приложения в файлы — пригодится, если что-то сломается» / "Write what
  the app does to files — useful if something breaks"; по умолчанию включён.
- «Хранить» / "Keep": «День», «3 дня», «Неделя», «Месяц» / "A day", "3 days", "A week", "A month" — 1, 3, 7, 30 дней,
  по умолчанию 7. Чужое значение в настройках — неделя.
- Журнал выключен — «Хранить», «Открыть папку» и «Сохранить журнал…» недоступны.
- В `settings.json` — `logEnabled` и `logRetentionDays`, как соседние ключи.

**Файлы** в `%LOCALAPPDATA%\Melogold\logs`:
- Каждый запуск пишет в `melogold-ГГГГММДД-ЧЧММСС.log` (местное время начала файла). Новый файл (с новым временем в
  имени) — когда текущий дорос до 2 МБ или сменилась дата. Падение — по-прежнему `last-crash.txt`.
- `current.log` и `previous.log` прежних версий — тоже `*.log`: не переносятся, уходят по сроку сами.

**Уборка** — при старте, при начале каждого нового файла и при смене «Хранить»: `*.log` и `last-crash.txt`, у которых
время изменения старше срока; затем, если всё вместе больше 50 МБ, — самые старые по времени изменения, пока не станет
не больше 50 МБ. Файл, в который идёт запись, не удаляется.

**Выключение** — запись прекращается сразу: ничего не пишется, падение в `last-crash.txt` не пишется; все файлы папки
`logs` удаляются сразу, вместе с файлом этого запуска. Включение — сразу новый файл, без перезапуска.

**«Сохранить журнал…»** (0039): шапка, как была, и строка «Журнал: хранить 7 дн.»; затем «===== Падение
(last-crash.txt) =====», если оно есть, затем все `*.log` от старых к новым по времени изменения, у каждого —
«===== melogold-20261031-134500.log =====».

## Как сделано

- `LogFiles` (Core) — правила папки без Windows: `FileName`, `NeedsNewFile`, `RetentionDays`/`Retention`, `Logs`,
  `Clean(папка, сейчас, срок, пишущийся файл)`, `DeleteAll`. Уборка и удаление не бросают: их зовёт журнал на старте;
  файл, который не удалился (открыт другой программой), ждёт следующей уборки.
- `Log` (App): настройки читаются раньше журнала, поэтому `App` создаёт `SettingsStore` до `Log.Start(settings)` и
  отдаёт тот же экземпляр в контейнер; строки до старта (предупреждение о нечитаемых настройках) журнал держит в памяти
  и дописывает в файл после первой строки или выбрасывает, если журнал выключен. Смена «Журнал» и «Хранить» доходит до
  журнала через `PropertyChanged` настроек. Файл той же секунды (включили снова, перезапуск) дописывается, а не затирается.
- «Диагностика» — `SettingsExpander`, как карточки кэша: «Открыть папку» и «Сохранить журнал…» — в шапке карточки,
  «Журнал» и «Хранить» — внутри. Журнал выключен — карточка открывается раскрытой, чтобы было видно, почему кнопки
  недоступны. Диктору выбор срока называется «Сколько хранить журнал» / "How long to keep the log" (только Windows).

## Проверка

- `LogFilesTests`: имя по времени начала; новый файл на 2 МБ и в новую дату; сроки и чужое значение; по сроку уходят
  журналы, падение и `current.log` прошлой версии, а чужой файл и пишущийся остаются; «день» — 24 часа; больше 50 МБ —
  уходит самый старый, пишущийся (старше всех) остаётся; ровно 50 МБ остаются; выключение — папка пуста.
- `LogReportTests`: шапка со сроком; падение первым, журналы по времени изменения, а не по имени (`previous.log` — старше
  всех); без падения нет его раздела; чужие файлы не входят; журнал, открытый на запись, читается.
- Прогон `Log` и `SettingsStore` приложения на Linux (временный проект, Windows-часть заглушена): старт убрал
  `previous.log` старше недели, «Хранить: 3 дня» — файл четырёхдневной давности, выключение — все файлы, падение не
  записалось; включение — новый файл без перезапуска; `logRetentionDays` в `settings.json`.
- Вживую на Windows: переключатель, выбор срока, недоступные кнопки при выключенном журнале, снимки карточки.
